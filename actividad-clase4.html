🪜 2. REST o Eventos

Interacción REST Evento ¿Por qué?
1 X El cliente necesita una respuesta inmediata (OK/Error) para saber si su pedido fue recibido.
2 X El pago debe validarse en tiempo real antes de avisar al restaurante; no podemos "esperar a ver si pasa".
3 X Una vez pagado, lanzamos el evento "Pedido_Listo" para que los repartidores disponibles se enteren sin bloquear el flujo.

🪜 3. Síncrono o Asíncrono

Interacción Síncrono Asíncrono Justificación
1 X El cliente no puede cerrar la app sin saber si su pedido entró al sistema correctamente.
2 X Necesitamos confirmar el pago de inmediato para autorizar la preparación de la comida.
3 X La búsqueda de repartidores puede tomar tiempo; no bloqueamos el sistema mientras un repartidor acepta.

🪜 4. Eventos Importantes del Sistema

1️⃣ Este evento se dispara cuando el pago es exitoso. Avisa simultáneamente al Restaurante para que empiece a cocinar y al Servicio de Facturación para generar el recibo.
2️⃣ Se emite cuando un "Rappitendero" acepta el pedido. Notifica al Cliente (push notification) y le da al Restaurante la señal de que alguien ya viene en camino por la comida.
3️⃣ Es el evento final. Dispara el proceso de Calificación (encuesta), libera el pago retenido al repartidor y actualiza las estadísticas de ventas del comercio.
